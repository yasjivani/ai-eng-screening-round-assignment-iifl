# IIFL Finance — Policy-Aware Customer Support Agent

A small AI-assisted prototype for the IIFL Finance Round 1 screening assignment.

## How it works
1. `src/ingest.py` extracts text from the three policy PDFs in `data/raw/` and writes `data/chunks.json`.
2. `src/retriever.py` uses BM25 keyword retrieval with a small domain-synonym expansion layer.
3. `src/agent.py` retrieves the most relevant policy chunks before calling OpenAI.
4. The model is instructed to answer only from the retrieved policy context and returns validated structured JSON.
5. Low/zero retrieval matches, malformed model output, LLM failures, and ungrounded answers are escalated.
6. `src/cli.py` provides a simple local command-line interface.
7. Tests use an injected stub LLM, so the core agent tests do not require an API key.

## Why this approach
BM25 is sufficient for the small policy corpus and is easy to inspect and debug. It avoids unnecessary vector-database infrastructure while still handling domain terminology through controlled synonym expansion. OpenAI is used only after retrieval, reducing unnecessary model calls.

## Before production
- Add stronger document/version governance and automated ingestion validation.
- Add PII controls, audit logging, access control and secrets management.
- Add retrieval/evaluation datasets and monitoring for false-positive/false-negative escalations.
- Add prompt-injection defenses and stronger citation/grounding verification.
- Use an approved enterprise OpenAI configuration and review data-retention/residency requirements.

## Financial-services security/governance concern
Customer questions can contain sensitive financial or personally identifiable information. The system should minimize what is sent to an external model, enforce approved data handling and retention controls, and prevent account-specific information from being inferred from generic policy documents. All generated answers should remain auditable against the source policy version.

## AI coding tools
ChatGPT was used to reason through the project structure, implementation, debugging and test cases. The implementation remains intentionally small and locally runnable, matching the assignment's time-boxed prototype requirement.

## Setup

Python 3.11+ is recommended.

### 1. Create and activate the environment (PowerShell)

```powershell
python -m venv iifl_venv
.\iifl_venv\Scripts\Activate.ps1
```

### 2. Install dependencies

```powershell
python -m pip install -r requirements.txt
```

### 3. Add the policy PDFs

Put the supplied PDFs in:

```text
data/raw/
```

The expected local structure is:

```text
data/raw/
├── Co-Lending Mechanism.pdf
├── Interest Rate & Charges Policy.pdf
└── Tax Policy_IIFL_Final.pdf
```

The ingestion script processes every PDF in `data/raw/`, so filenames can differ.

### 4. Build the retrieval index

```powershell
python -m src.ingest
```

This creates:

```text
data/chunks.json
```

### 5. Configure OpenAI

Copy `.env.example` to `.env` and add your API key:

```text
OPENAI_API_KEY=your_key_here
OPENAI_MODEL=gpt-4o-mini
```

Do not commit `.env`.

### 6. Run the CLI

```powershell
python -m src.cli "What is the interest rate range for a gold loan?"
```

Or run interactively:

```powershell
python -m src.cli
```

### 7. Run tests

```powershell
python -m pytest -v
```

Tests use a stub LLM and do not make OpenAI API calls.

## Example output

The exact answer depends on the supplied policy documents. A successful response has this shape:

```json
{
  "query": "What is the interest rate range for a gold loan?",
  "category": "interest_rates_and_charges",
  "answer": "...",
  "source": "Interest Rate & Charges Policy.pdf ...",
  "confidence": "high",
  "action": "respond"
}
```

For an unsupported/off-topic question:

```json
{
  "query": "Who won the cricket world cup in 2011?",
  "category": "out_of_scope",
  "answer": "I can't answer this from the published policy documents. I'm routing it to a human support executive who can help.",
  "source": "none",
  "confidence": "low",
  "action": "escalate"
}
```
